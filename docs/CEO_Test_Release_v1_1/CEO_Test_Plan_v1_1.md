## 7. 执行顺序原则

1. **先自动后人工**：每轮先跑对应 Vitest，再按案例做 UI/真机观测；自动化失败不进入人工步骤。
2. **先主链后分支**：R1 不通不进入 R2；R2 财务不一致不进入 R3。
3. **先破坏性后收尾**：存档损坏、关闭公司、断网放在 R4/R6 后段，避免污染后续用例。
4. **每轮独立存档**：轮次开始清档或载入指定夹具，禁止沿用上一轮脏状态。
5. **时间类用例集中做**：倍速/离线/暂停一次连续执行，减少等待与状态漂移。
6. **失败即留证**：失败案例必须保留状态 JSON、账本、截图/录屏，不允许只写“失败”。

## 8. 缺陷管理与回归

| 等级 | 定义 | 处理 |
|---|---|---|
| S1 阻断 | 崩溃/白屏/无法启动；存档丢失；资金或账本错误；旧公司复活；离线重复领取 | 立即停轮，修复后全链路回归 + 黄金复跑 |
| S2 严重 | P0 功能不可用但有绕行；主操作被遮挡；救助/裁员/建部费用异常 | 当日修复，回归所在场景 + 相邻场景 |
| S3 一般 | P1 功能异常、可解释性不足、非主链 UI 问题 | 轮内修复，回归该案例 |
| S4 轻微 | 文案、间距、图标风格 | 记录并排期，发布前修复或明示遗留 |

缺陷单必填：案例 ID、环境/设备、前置夹具、复现步骤、预期/实际、差额、证据路径、引入版本、修复验证人。禁止删除失败案例，禁止用开发自述替代 QA 复测。
