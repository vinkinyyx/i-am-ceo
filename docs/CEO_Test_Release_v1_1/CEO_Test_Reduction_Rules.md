# 精简依据、风险边界与发布门禁

## 旧版为什么显得过多

- 把同一费用公式不同年限列成多个独立测试（例如裁员任职0、1、2、3、4、5、10年）。本版只保留代表性0年与3年，并使用参数表验证同一公式。
- 把1×、2×、5×、月末、帧率差异拆成大量时钟用例。本版合并到一个倍速对照，再保留暂停与年度结算。
- 存档双槽、CRC、超时、底层写失败逐故障细分。本版保留正常读写、单槽恢复、版本升级，不将多项底层故障注入全部设置为人工首发门禁。
- 33页UI逐页独立测试且额外检查全部Loading/Empty/Error状态。本版统一为33页巡检表+4条组合页面检查、另2条适配/文本用例。
- 去掉长时间压力、100年年报、100名员工和大量随机种子测试，仅保留一次完整经营流程。

## 真正要保留的高风险项

1. 资金只初始化一次；录用/裁员/建部不能错误扣款，财务年报与现金可对账。
2. 三个行业首年财务与12个月汇总，现金/资本支出/折旧区分。
3. 1×/2×/5×、暂停、离线上限和回到前台不重复补领。
4. 亏损≠破产；资金困难与一次救助正常；退出困难后恢复结算。
5. 本地存档能够恢复，关闭公司后旧公司不会复活。
6. TapTap真实安卓设备完成完整经营流程，音乐与音效总开关有效。

## 发布判定

- P0 57条应全部通过；P1 23条重点关注玩法、UI及发布合规。
- **禁止对未运行的用例填写通过**。缺陷重大性比用例总数更重要；一旦发现漏记账、存档丢失、资金错误，应补充针对性回归。
- 保留17项原有数值黄金参考，其中关键三行业、资金、离线、赔偿、资产必须验证；其余作为自动化回归资料。
- 不把未实现的手工调岗、上市、股票、子公司、云存档、真人排行榜写成首发必验。

## 变更触发专项测试

经营参数、裁员计算、存档协议、SDK版本、UI路由如有代码变更，补测对应功能即可，不必自动恢复315条全量执行。
