# 10｜分批实施任务书、Agent协作契约与门禁

> 这是**执行任务列表**，每个任务可交给不同Agent独立完成，任何Agent接手前必须读取README、00、对应专项文件和`11`决策台账。任务完成后更新执行状态，不直接改已确认需求。

## 10.1 项目职责与仓库约定

- 需求Owner：用户；可决定范围、玩法、数值方向。
- 技术主Agent：维护架构、代码合并、接口和CI，保证不会出现两份领域算法。
- 子Agent：按TASK ID开发、测试、提交证据。不能绕过前置任务。
- QA Agent：独立根据09的黄金用例验证，不以开发Agent“已通过”自述代替复测。
- 发布Agent：根据08核查真实TapTap后台/构建日志/授权、备案、物料。

仓库主线`main`保持可编译；单任务分支`feat/TASK-Mx-xx`；任务中必须注明`codeChanges`, `docsUpdated`, `testsAdded`, `screenshots`, `risks`。不允许将临时测试账号、平台私钥或用户隐私提交。

## 10.9 提交发布前变更控制

- 任何经济参数修改都需更新`economy.v1.json`版本、golden-cases和财务测试，并记录改变理由与受影响存档版本。
- 修改核心公式/金额结转规则须附跨行业黄金用例和性能回归证据。
- 修改关公司/存档协议须附断电恢复、旧run阻断测试。
- TapTap官方文档更新时，仅更新对应平台适配实现，避免影响本地纯业务规则；如平台要求与产品设定冲突，先由产品Owner确认。
- 任务只有经过独立验收才能改`DONE`；创建分支和写代码不算完成。
