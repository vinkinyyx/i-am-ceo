# 《我是CEO》第一阶段 MVP — 可执行开发设计包 V1.0

> 编写日期：2026-11-01｜目标发行：TapTap 普通小游戏（不是 H5/Android APK）｜开发建议：Cocos Creator 3.8.x + TypeScript  
> **状态：设计基线；未编写/未验证游戏工程，未完成TapTap开发者认证、备案或上架。**

## 立即开始

1. 阅读 `00_范围_规则_冲突处理.md`，不自行扩大第一阶段功能。
2. 阅读 `01_整体架构_目录与接口.md` 和 `02_核心数据模型_存档与重置.md`，按接口先实现领域层，不把平台SDK散落在业务代码中。
3. 实现 `03_模拟时钟_结算_财务引擎.md`，先通过财务黄金用例，再制作可视化界面。
4. 按 `10_实施任务_交付门禁与Agent协作.md` 的 **TASK ID** 逐个执行。每次交付必须附测试证据、变更清单、遗留问题；不允许只报“完成”。
5. TapTap 实际接入前再核验 `08_TapTap适配_审核与交付.md` 中的官方文档，不能把开发环境模拟接口当成真实平台接口。

## 文档目录

- `00_范围_规则_冲突处理.md`：已确认需求、不做事项、优先级、核心不变量、旧版本纠偏。
- `01_整体架构_目录与接口.md`：Cocos工程结构、模块依赖、服务接口、事件/错误规范、构建与质量门禁。
- `02_核心数据模型_存档与重置.md`：类型字段字典、关系、版本迁移、双槽存档、反复重开安全、数据大小预算。
- `03_模拟时钟_结算_财务引擎.md`：逐月状态机、收入/成本公式、整型金额、幂等、离线、危机与金钱守恒。
- `04_行业参数_数值平衡.md`：三行业差异、初始样例、成本中心的量化效果、5年样例生成方法。
- `05_CEO_员工_候选人与裁员.md`：随机命名、CEO、候选人生成、聘用、成长、裁员、费用计算。
- `06_部门_自动经营_策略.md`：建部门、员工分派、可预览投入产出、自动招聘、优先级与资金约束。
- `07_页面路由_UI组件_新手引导.md`：竖屏页面规范、状态、逐点击指引、错误提示、触屏验收。
- `08_TapTap适配_审核与交付.md`：小游戏SDK适配、最小后端边界、官方核验、合规材料、真机发布清单。
- `09_测试设计_黄金用例.md`：测试分层、预期输出、边界矩阵、端到端证据。
- `10_实施任务_交付门禁与Agent协作.md`：M0—M3任务清单（可分派）、依赖关系、DoD/交接模板。
- `11_规则与待校准项登记.md`：确定/暂定/待平台确认，不让Agent擅改基线。
- `12_业务命令接口_状态机与异常.md`：每一业务动作的输入、授权状态、资金结转、幂等和错误处理。
- `13_视觉资源_组件规格与交付约定.md`：必要图标、人物头像、组件尺寸、打包与美术QA。
- `配置与测试数据/economy.v1.json`：机器可读基准参数（属待平衡测试值）。
- `配置与测试数据/golden-cases.v1.json`：黄金样例与计算不变量。
- `配置与测试数据/save.schema.json`：存档数据JSON Schema初始契约。
- `工具/校验设计基线.py`：可执行的一致性校验（不代表已经验证实际游戏）。
- `研发过程记录/执行状态模板.md`：每个Agent维护任务执行状态的模板。
- `原始需求_V0.9_归档参考.md`：前版需求，仅供追溯；冲突时以本设计包正文和决策登记为准。

## 一票否决项

- 使用真实资金、广告、内购、跨行业、子公司、集团、贷款、真实在线排名或复杂生产线。
- 经营算式仅在 UI 中实现；月份重复结算；公司重开后旧存档复活；无确认自动裁员。
- 用浏览器 `window/localStorage/document` 作为 TapTap 运行时依赖，或把客户端密钥写入游戏。
- 把总资产当成累计收入或公司估值，把投资款当利润，把部门节约重复入账。
- 文档声称已经通过TapTap审核但没有开发者后台/真机证据。

## 文档更新规则

文档不一致时优先级：本 README 的产品边界 → `00` 中 P0已确认规则 → `11` 决策台账 → 业务/技术专项文件 → V0.9归档。技术实现发现冲突必须先更新 `11` 并提交差异记录；不得静默改变玩家已确认要求。
