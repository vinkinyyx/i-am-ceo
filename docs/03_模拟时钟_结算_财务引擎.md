# 03｜时间模拟、月结、年结、离线与财务引擎

## 3.1 唯一的时间语义

- `gameYear=1, gameMonth=1`：本轮的第1年、第1个待结算月；游戏内的年份标签可固定为“创业第1年”，不绑定真实2026年。
- 正常在线：一经营年300000ms，1个月25000ms；2×/5×线性缩短**真实耗时**，不改变经济结算量。
- 暂停：`speed=0`，在线不累积进度，离线也不结算。
- 离线：8小时实际时间=12个月等效，**每完整40分钟形成一个游戏月**；最多结算36个月。离线不受离开前的在线加速倍率影响，避免5×挂机套利。
- 离线不足40分钟的余量记录`offlineRemainderMs`，下一次离线可以继续累积；超过24小时的部分当次丢弃，不留“欠发”信用。返回前台先计算离线、提交存档，再恢复在线时钟。
- 手机时间回拨（now<lastWallClockMs）：不产生离线收益，更新水位需防回拨漏洞；设UI提示设备时间异常；正式方案若无可信服务器不能保证抗时钟作弊，只保证不会负结算/无限累计。

## 3.2 月结顺序：不得调换

```text
advanceMonth(state, config):
  assert RUNNING/DISTRESS, monthKey not previously posted
  1. 使用月初已生效员工和部门，读取本月经营策略及现金安全阈值
  2. 依年度已生成的市场趋势、当年唯一事件生成本月需求参数
  3. 执行预算内的自动招聘决策（本月支付费、下个月才开始上岗）
  4. 计算主营业务交付能力与潜在订单 → 本月对外营收
  5. 按适用基数计算直接成本/营销外业务经营费/售后费/固定费用
  6. 计算采购/客服/财务净节约、市场的需求增益；同种节约只扣一次
  7. 计算本月已生效人员工资、费用、一次性支出、事件损益
  8. 计算损益利润、现金净流入、业务资产折旧/资产变动
  9. 应用玩家先前确认的资本性投入/已支付事件项，不重复计款
  10. 生成唯一 MonthlyLedger，更新期末现金与资产/风险
  11. 如果本月是12月：汇总年度报表、员工/CEO年度成长、更新模拟排行
  12. `lastSettledMonthKey` 前移，游戏月份+1，保存新快照
```

**风险处理**：若拟支付刚性费用超过可用现金，不允许余额变负；进入`DISTRESS`，该月模拟不能生成伪利润或把员工工资忽略。具体策略：先以能够完成的收现订单预测本月付款能力；不足时停止本月自动投资和招聘，若仍无法覆盖必要费用，冻结推进于该月、弹出经营困难并等待玩家动作/一次性资本救助。被冻结的月不生成Ledger，防止重试月份重复冲销。上线前需要模拟极端现金不足并验证能否恢复。

## 3.3 收入与产能公式（定义准确单位）

所有金额元为整数；`basisPoints`使用整数。

```text
行业基准潜在年订单 D_y（元）= D_1 * 年度需求指数（受增幅和事件影响）
当月基础订单 D_m = distribute(D_y,12,month)
市场系数 Acq = clamp(10000 + CEO商业增益 + 市场部增益, 8500, 13500)
可获客订单 A_m = round(D_m * Acq / 10000)
主营部产能 C_m = sum(行业单人年产能/12 × (7000 + skill*50)/10000)
  × collaborationCoeff × ceoManagementCoeff × businessAssetCoeff × hrBusinessCapacityCoeff
实际营业收入 Revenue_m = round(min(A_m, C_m) * completionRateBps / 10000)
```

基础情况下：能力60→系数1.0；团队协作50→1.0；CEO管理50→1.0；首年成交完成率100%。`completionRate`普通状态100%，事件时下降但不变负值。

> 不能将初始业务基准行业产能80万元写成必得营业额。第1年贸易是需求72万、标准2名员工产能80万，所以实际72万。

### 系数更详细规范

- `collaborationCoeffBps = clamp(10000 + (业务部门员工平均teamwork-50)*20, 9000, 11000)`，对应0.9~1.1。
- `ceoManagementCoeffBps = clamp(10000 + (CEO.managementSkill-50)*20, 9000, 11000)`。
- `ceoBusinessBps = clamp((CEO.businessSkill-50)*15, -750, 750)`，即最大约±7.5%影响潜在订单；不会强制收入超过产能。
- HR产能加成 `hrBusinessCapacityCoeffBps = 10000 + hrBusinessCapacityBonusBps`（0员工=0，1位标准HR+600bps，封顶+1200bps，按04的查表法与能力系数计算）。
- 业务资产扩张加成 `businessAssetCoeffBps = 10000 + min(3000, floor(businessCapacityInvestmentYuan/10000)*150)`：每投资1万元，产能+1.5%，最多+30%；随资产投入累计，不随折旧立即失去已购买产能（本阶段简化）。
- `completionRateBps`默认10000，事件或极端员工不足时变更，但不得大于10000。

## 3.4 费用拆分与“只节省一次”

对于单月收入`R`：

```text
baseDirect = round(R * industry.directCostBps / 10000)
baseOtherOps = round(R * industry.otherOpBps / 10000)
baseAfterSales = round(R * industry.afterSalesBps / 10000)
baseFixed = distribute(industry.fixedCostAnnualYuan, 12, month)
procurementEligible = round(baseDirect * industry.procurementEligibleBps / 10000)
procurementSaving = min(procurementEligible, round(procurementEligible * procurementSavingRateBps / 10000))
customerSaving = min(baseAfterSales, round(baseAfterSales * customerServiceSavingRateBps / 10000))
financeEligible = baseFixed + baseOtherOps  // 财务管理可控成本，不含工资/直接成本/售后
financeSaving = min(financeEligible, round(financeEligible * financeSavingRateBps / 10000))
financeFixedAllocated = min(baseFixed, financeSaving)
financeOtherOpsAllocated = financeSaving - financeFixedAllocated
directPaid = baseDirect - procurementSaving
operatingPaid = baseOtherOps - financeOtherOpsAllocated + baseAfterSales - customerSaving
fixedPaid = baseFixed - financeFixedAllocated
payrollPaid = sum(当月实际生效员工月薪)
profit = R - directPaid - operatingPaid - fixedPaid - payrollPaid - hireExpense
         - severanceExpense - deptSetupExpense - eventExpense - depreciation
cashDelta = R - directPaid - operatingPaid - fixedPaid - payrollPaid - hireCash
            - severanceCash - deptSetupCash - eventCash - capexCash + capitalInjectionCash
```

市场部的效果体现在`A_m`，不得再追加一笔“市场销售利润奖励”。HR效果体现在**尚未支付的招聘费折扣**和主营业务员工的产能加成（1人基准+6%，上限+12%）；产能加成只有在订单充足时才增加营业额，绝不能没有订单就直接增加现金。一次性招聘费/裁员/设部可能在月中点击时即已实际扣现金，**必须以pendingEntries记账并在后续月结聚合；现金不能被月结再次扣减**。严格区分两种量：

- `ledger.cashDeltaYuan`：归属于该月的**全部现金变化**，包含此前确认操作中已实际支付的招聘/裁员/设部/投资款，以便年报勾稽。
- `unpaidCashDeltaYuan`：本次模拟月结仍需实际更新`company.cashYuan`的增量，**不包含**`pendingEntries.alreadyPaid=true`的款项。

执行月结时只将`unpaidCashDeltaYuan`应用到当前现金余额。年报按12个月`ledger.cashDeltaYuan`加总对账；首聘费用计第1年月账但在创建期间已经支付，详见`12`的完整贸易月1示例。

## 3.5 金额取整与对账

采用`MoneyYuan: number`整数，严格`Number.isSafeInteger`。基点乘除统一`roundHalfUpNonNegative(a*bps,10000)`（对费用/收入非负）；数额为负时先算绝对值后还原符号。年度最后一个月可用累计残差法分配比例费用，让固定费12个月总额恰等于配置年额，百分比费与年度总收入的差值不得超过数元（黄金样例按无事件精确校准）。不要四舍五入`现金+利润`合计后再倒推出各类费用。

`CHECK(annualRevenue == sum(12.monthRevenue))`；`CHECK(annualProfit == sum(12.monthProfit))`；`CHECK(endCash == yearOpeningCashBeforeAnyPayments + sum(month.cashDelta))`；`CHECK(endAssets == endCash + endBusinessAssetBook)`。

## 3.6 业务扩张（最简单的单一按钮）

- 可以在主营业务卡片点击“扩大产能”，按**1万元为步长**决定投资，不能超过可用现金安全额度；MVP不生产实体设备/库存。
- 确认一次性现金支出、增加`businessAssetBookYuan`及`businessCapacityInvestmentYuan`，即时总资产不变；从下一年开始对本年度新增资产按年10%折旧（每月累加总计），不能再当期全额扣利润。
- 扩张后预计营收未必增长：如果市场需求不足，UI必须提示“当前订单需求不足，新增产能可能闲置”。
- 经营困难时停止扩张；不自动投资，避免挂机失去大额现金。

## 3.7 年度市场趋势与事件

- 玩家创建时确定一个市场种子，按年份确定`D_y`；年度基础自然增长首轮配置10%（测试可调8%—12%），不得叠加为“每月10%”。
- 事件池仅5种：订单临时增加、订单临时减少、采购/成本上涨、员工意外离职、一次性设备/售后损失。
- **每游戏年最多一次，概率25%**。使用`hash(seed, runId, year, 'event')`决定是否发生、类别与发生月份，独立于UI随机刷新次数，以保证反复加载不改变事件。
- 员工意外离职：事件从次月移除岗位，**不收裁员赔偿**，但产生明确的下一年度招聘风险；不会自动引发第二事件。
- 订单与费用事件影响范围不超过相关基数的5%—12%；损失需通过正经成本项入账；其金额列示在年报。
- 事件具体触发月份后不应再对已经结算的月份产生追溯调整。

## 3.8 年报与连续盈利

年末：`totalAnnualProfit = sum(MonthlyLedger.profitYuan)`；若`>0`则`consecutiveProfitableYears +=1`，否则归零。达到3设置`target3YearsAchieved=true`并保留历史；允许继续经营。亏损不重置公司、CEO、资产或员工。年报保存分类费用、总收入、利润、开/末现金、资产、人员、部门、事件和经营诊断建议；年报作为快照，后续不得修改旧年度。

## 3.9 离线与前后台伪代码

```ts
async function settleOffline(nowMs: number, state: GameState) {
  if (state.speed === 0 || state.phase !== 'RUNNING') return noWork();
  const safeGapMs = Math.max(0, nowMs - state.lastWallClockMs);
  const eligibleMs = Math.min(safeGapMs, 24 * 60 * 60 * 1000);
  const credit = eligibleMs + state.offlineRemainderMs;
  const months = Math.min(36, Math.floor(credit / (40 * 60 * 1000)));
  const newRemainder = months === 36 ? 0 : credit - months * (40 * 60 * 1000);
  for (let i = 0; i < months; i++) {
    const result = await advanceOneMonthAtomically(state, 'OFFLINE');
    if (!result.ok) break; // 遇风险中断，不凭空跳月
    state = result.state;
  }
  state.offlineRemainderMs = newRemainder;
  state.lastWallClockMs = Math.max(nowMs, state.lastWallClockMs);
  return commitAndSummarize(state);
}
```

**实现注意**：如遇资金危机中断，尚未使用的离线时长不得无限保留供重试套利；按已经处理的月份与封顶策略明确记录 `consumedOfflineMonths`。如果在中断后把全部余量继续保留，可能每次回归都反复向同一风险月尝试，需有针对性单测。

**在线**：每帧拿`deltaTime`累计到逻辑进度，`elapsed *= speed`；只在累计≥一个游戏月时触发一次原子月结，直到消费完积累。后台恢复期间暂停在线时钟，处理完离线后才恢复。若用户操作了“暂停”，任何时钟源都不继续结算。

## 3.10 财务风控与一次救助

- 风险分层：预计未来6个月固定支出覆盖不足→`WARNING`（黄色）；当前月必要费用经预测仍无法支付→`DISTRESS`，冻结新增投资/招聘/无法负担的月结，保留存档。
- 玩家可：将部门人员手动调整为0（解雇补偿仍需资金）、切换稳健、降低未来预算、等待当前业务收款，或领取**一次性**10万元CEO追加资本。资金救助为新增投入资本，**不算收入/利润**。
- 不实现正式破产、贷款或自动裁员。后续平衡测试要确保没有无法交互的死锁：如果即使追加资金仍无法运营，至少允许玩家主动关闭重开，且明确告知。

## 3.11 结算故障必须测试

- 前后台快速切换10次、速度5×在年末临界切换、杀进程月结中断、系统时间回拨24小时、40小时离线封顶、存档写失败、随机事件单年度重复读档、关闭公司与月结竞态。
- 每个测试输出两个证明：**Ledger明细**、**当月/年度State变动**。不能只验证页面显示利润。
